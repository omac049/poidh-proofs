I built an app

In your app’s public GitHub repository, run:

In your repository
npm i -g menloapp
menloapp deploy

You get a link to send, like https://menloapp.lol/your-app. After that, pushing to the default branch is enough: the same link follows the latest commit.

deploy signs in to GitHub with a device code you approve in a browser, finds your Xcode project and scheme, and prints the link.

menloapp init creates or edits your app page before you deploy: icon, name, subtitle, up to three screenshots, a preview recording and a description, from menloapp/app.json and media committed in the repository. Also: menloapp open, menloapp doctor, menloapp --help.

Discover apps on menloapp.lol

What a link promises, and what it doesn’t

A Menlo link points at public source. It is not a verdict on it.

A Menlo link tells you

  • Who published it
  • Which repository it comes from
  • Which exact commit

It does not tell you

  • That the app is safe

That judgment belongs to whoever reads the source and chooses to build it: you, or someone whose review you trust.

Exact-version links

A plain link follows the latest commit, so what it opens can change. An exact-version link pins one commit. Use one when you recommend code you reviewed.

Exact-version link
https://menloapp.lol/<slug>?commit=<sha>&repository=<id>

Reviews

Anyone can publish, under their GitHub account, that they reviewed one exact version, and name what they examined:

  • source
  • dependencies
  • entitlements
  • permissions
  • networking
  • privacy
  • payments
  • reproducibility

A review covers one commit and never carries over to a newer version. Reviews say what someone examined. They are not a safety guarantee.

Terminal
npx menloapp review '<exact version link>'

Menlo never hosts your source, never holds your tokens, and never builds or signs for anyone.

It stores only a small public listing: slug, repository, Xcode project and scheme. The repository is the app.

What you need

To share

  • Node.js 20 or newer
  • git
  • A GitHub account with push access to the public repository

The repository must be public on GitHub, with a committed Xcode project or workspace for an iOS app.

To install

  • A Mac with macOS 14 or newer
  • Xcode
  • An Apple ID
  • The iPhone the app is for

Menlo for Mac is a release candidate.

For agents

Coding assistants and AI agents can read https://tohseno.com/llms.txt to deploy, install or review apps on a person’s behalf. A human still approves the GitHub sign-in and any review.

Questions

Is this an app store?

No. There is no store, no approval wait and no hosting. The repository is the app.

Does Menlo build my app?

No. The person installing it builds it on their own Mac, with Xcode, and signs it with their own Apple ID.

Which apps work?

Public GitHub repositories with a committed Xcode project or workspace for an iOS app.

How do I update my app?

Push to the default branch. The link follows the latest commit.

Is it safe?

A link names who published the app, which repository and which commit. Whether it is safe is judged by reading the source. Reviews record what someone examined; they are not a guarantee.
